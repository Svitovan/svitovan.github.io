Privacy Policy

Application: Calendar for Hermes · Last updated: 6 October 2026

1. What this application is

Calendar for Hermes is a private, single-user OAuth 2.0 client. It lets its owner (Aleš Janáček, alex.yanchyk@gmail.com) use their personal Hermes Agent assistant to view and manage the owner's own Google Calendar and Google Tasks. It is not a public service, it has no other users, and it is not distributed.

2. What data it accesses

  • Google Calendar — event titles, start/end times, locations, descriptions and attendee lists (https://www.googleapis.com/auth/calendar). The application may create, update and delete events, always at the owner's explicit request.
  • Google Tasks — task lists, task titles, due dates and notes (https://www.googleapis.com/auth/tasks), with the same read/write nature.
  • Account identifier — the email address of the account that authorized the application, used only to bind the stored token to that account.

3. How the data is used

Only to carry out the owner's own instructions, for example: showing the day's schedule, creating an event, listing or completing a task. The data is not used for advertising, profiling, analytics, or training of any model, and it is not used for any purpose beyond answering the owner's request.

4. Where the data is processed and stored

  • Requests go directly from the owner's own self-hosted computer to Google's APIs. There is no intermediate server, no cloud database and no third-party processor.
  • OAuth tokens are kept locally on the owner's machine in a permission-restricted file (~/.hermes/google_token.json, mode 600). Tokens are never sent anywhere except to Google's own token endpoint.
  • Calendar and task content appears only in the owner's own assistant session and logs on that machine. Nothing is sold, rented, shared or disclosed to third parties, except where required by law.

5. Retention and deletion

  • The application keeps no separate copy of Google data in any remote store under its control.
  • Access can be revoked at any time on Google's Third-party apps & services page, which immediately invalidates the stored token.
  • Deleting ~/.hermes/google_token.json on the owner's machine removes the local credential as well.

6. Security

  • OAuth 2.0 authorization-code flow with PKCE; the requested scopes are limited to calendar and tasks.
  • All communication with Google runs over HTTPS. The local token file is readable only by the owner's user account.

7. Children and commercial use

Not applicable — the application is not offered to the public, has a single user (its owner) and is not used commercially.

8. Changes

Any material change to this policy will be published on this page with an updated date.
